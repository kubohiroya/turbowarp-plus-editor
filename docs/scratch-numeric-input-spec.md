# Scratch数値入力の仕様メモ（全角数字・小数・整数の扱い）

対象：TurboWarp-Plus-Editor の数値引数欄
状態：草案（実装前。Scratch 実行時の挙動は未検証）

## 1. 背景

- 日本語 IME で入力すると、全角数字（例：「１２３」）が数値欄に入力できてしまう。
- Scratch の数値欄は、利用者にとって数値として扱われているように見えるが、全角数字は計算で正しく扱われない。
- 私の理解では、Scratch 実行時は非数値を `0` として扱うため、エラーが出ず無言で `0` になる可能性が高い。この点は実際の挙動を確認してから断定すること。
- 英語圏フォーラムでも、日本の利用者による同様の報告がある（有効な数字かどうかを判別する機能を求める投稿）。Scratch 公式による注意喚起や修正は今回の調査では見つからなかった。

## 2. 用語定義

公式な規格名は見つからなかったため、本プロジェクトで次のように定義する。

| 名前 | 定義（半角のみ） | 用途 |
|---|---|---|
| `ScratchNumericInput` | `^[+-]?(\d+\.?\d*\|\.\d+)([eE][+-]?\d+)?$` | 座標、角度、秒数、拡大率など、一般の数値引数 |
| `ScratchIntegerInput` | `^[+-]?\d+$` | リストの番号、繰り返し回数、文字列の何文字目など、整数が前提の引数 |

- `ScratchNumericInput` は JSON Schema や ECMAScript の正式な名前ではない。ドキュメント内でのみ使う独自名である。
- ECMAScript の `StrDecimalLiteral` などは空白、`Infinity`、16進数も許すため、今回の要件より広い。そのまま採用しない。

## 3. 入力時の処理

1. 全角の `０`〜`９`、`－`（全角マイナス）、`．`（全角ピリオド）、`＋` を半角に変換する。
2. 変換対象は上記に限定する。NFKC 正規化の全面適用は行わない。
3. IME 変換中（`compositionstart`〜`compositionend`）は値を書き換えない。確定時（`compositionend`）に変換する。
4. 貼り付け（`paste`）にも同じ変換を適用する。
5. 全角の `ｅ` / `Ｅ` を指数表記として扱うかは未決定（後述）。

## 4. 確定時（Enter・blur）の処理

- 変換が行われた場合：控えめな通知（例：「全角数字を半角に変換しました」）を表示する。
- 変換後も定義に合わない場合：該当ブロックにエラーマークを付け、警告を表示する。
- 文字列欄（「こんにちは」を言う等）には、この変換と検証を適用しない。

## 5. 実行前の検査

- 全角のまま保存された、または外部から読み込んだプロジェクトに対し、実行前に検査を行い警告を出す。
- 対象は `ScratchIntegerInput` の引数に小数や不正値が入っている場合を含む。

## 6. 未決定事項

- 全角の `ｅ` / `Ｅ` を指数表記として許可するか。
- `ScratchIntegerInput` で `1.0` のような値を許可するか（整数として扱うか、警告するか）。
- Scratch 実行時の非数値の扱い（`0` になるか）を、実機で確認する。
- 既存の Scratch 公式フォーラム（日本語カテゴリ）で、公式の対応有無を検索する。

## 7. 参考

- 英語圏フォーラム：全角数字を計算で無効とする報告と、Web 拡張機能による回避の事例。
- 日本語フォーラム：全角数字を一文字ずつリストで照合して半角と同じように扱う回避策の解説。
- 数値欄の入力制約（小数点・負数の禁止オプション）を求める Snap! フォーラムの提案。
