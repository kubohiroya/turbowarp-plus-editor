# 段階解放と教材機能の実装計画

既存のIssue 724にあるGuide・紙芝居連携を起点とし、能力制御、編集許可、教材制作を小さな作業へ分ける。以下の作業IDは資料内の識別子であり、新しいGitHub Issue番号ではない。公開するIssue本文の追記案は、この計画から作成する。

## パッケージの責務

| 所有者 | 実装するもの | 渡すもの・境界 |
| --- | --- | --- |
| `turbowarp-plus-editor-guide` | 機能レジストリの解決、教材設定の検証、課題の状態、編集許可、GUI対象照合、Joyride、操作待ち、Scratchブロック | ホストが渡す参照と公開portを使う。GUI内部をimportしない |
| Editor本体 | 公開版の依存固定、起動時の入力、各機能への結線、統合確認 | VM、document、共有React、Blockly、読み書き・操作のportを渡す |
| 各機能パッケージ | 自分の機能の無効化、UI・検索等へのフィルター、操作前の許可確認 | 接続しない／提供しないときに従来のTurboWarp動作を保つ |
| workbench / code-views / sprite-panes | タブ、検索、ミニマップ、パレット、素材等へ同じ範囲制限を適用 | 非表示データへ別経路から移れないようにする |
| project-folder / sb3-toolchain | 設定の保持と参照変換、保存往復、章間の作品継続 | 既存形式との互換性と旧版への切り戻しを確認 |
| 紙芝居App | 既存Custom Actionの接続、キャンセル可能な教材結果待ち | 物語の状態と時間制限を管理。GUIのDOMを知らない |
| 紙芝居Samples等の教材側 | 台本、学習対象、固定ハンドラー、達成条件、素材、次章導線 | Guide対象IDと課題IDだけを使う |

独立パッケージの追加は、承認済みのGuide一つを基本とする。機能制御だけを理由に新パッケージを増やさない。大きくなった場合の分離は、その時点で配置を合意する。

## Scratch GUIとの接続方針

2026年11月27日の[確認基点](README.ja.md#根拠となるソース)では、GUIの`getHostIntegration()?.createWorkspaceAttachment`からEditorのworkspace attachmentを生成し、`site/plus-integration.ts`の`attachToWorkspace`へVM、document、Blockly取得口等を渡している。Guideの表示・待機はこの既存経路への結線を先に検討する。ホストが不要な場合のGUI側の戻り先は何も描画しない関数である。

この接続口が、ステージのドラッグやネイティブの変数書込みを変更前に拒否する契約まで提供しているとは扱わない。今回確認した`stage.jsx`と`variable-utils.js`にはGuideの編集許可確認はない。既存portで表示・変更前の判定を渡せればGUI差分はゼロにし、不足する操作は最小の汎用portと必要性を先に設計する。Guideの判定本体をEditor側のattachmentやGUIへ追加しない。

完全な編集制限が、既存接続口だけで実現できると現時点では断定しない。BlocklyのUIフラグだけでVMへの変更を止められるとも断定しない。GUIに接続が必要でも、許可規則、状態、対象照合、説明文の実装は独立パッケージに置く。本家コードを移植して分離したことにしない。

## 最初の縦断実装

最初の受け入れ対象は、第1章の入力欄一つと、第2章への遷移に限定する。

1. stock相当の画面で教材を開く。
2. Guideがロボットの移動量を指す。
3. その欄だけを変更し、「ためす」で動かす。
4. VM全体と紙芝居の実行世代を維持して、達成結果を受け取る。
5. 保存後に第2章へ移り、検索機能だけが追加される。

この時点でスプライト追加、素材編集、Git復元、別窓案内は受け入れ対象に含めない。通常の保存、許可範囲内のUndo、停止、終了は使える。

## 検証と受け入れ基準

| 境界 | 必要な検証 | 失敗とする例 |
| --- | --- | --- |
| 能力解決 | ゼロ、full、全プリセット、依存欠落、未知ビット、二重指定 | マスクを黙って修正して意図しない機能が増える |
| ゼロの編集画面 | 上流TurboWarpとの操作・メニュー・接続の比較 | 文書アイコンやPlus独自動作が残る |
| 無効化 | マウント、イベント、キーボード、復元、廃棄 | UIだけ消えて隠れたショートカットが動く |
| 設定 | ID重複、参照切れ、opcode不一致、古い教材版 | 不明な設定を無視して全編集が可能になる |
| opcodeの用途 | 追加許可と実行許可、ハット・shadow、呼出し先、保護された判定役 | 第1章の追加禁止を理由に既存の移動処理まで実行できない |
| 編集制限 | ドラッグ、数値・文字・IME、貼付け、Undo、タブ、素材、外部取込み | 一瞬書き換わってから戻す |
| 実行継続 | 物語の世代と制御役の動作、新試行への編集反映 | `stopAll`や作品再読込で進行をやり直す |
| 試行 | 二重クリック、古い完了通知、対象スレッド停止 | 前の試行の通知で次の課題が達成になる |
| Guide | 実際の固定ReactとJoyride、対象移動、対象消滅、閉じる | ツアー終了を課題達成として扱う |
| 待機 | 5分超の読取り・離席、停止、キャンセル、課題交代 | 紙芝居の30秒timeoutで教材が壊れる |
| 別画面 | 全外部ホスト、保存済み配置、パレットとバックパック | 別経路から外部ウィンドウが開く |
| 得点と直接変更 | 変数を表示してスライダー化、パネルの値変更、ステージのドラッグ | 正規の試行で得ていない得点・到着状態によってクリアになる |
| 保存 | SB3・フォルダ往復、Guide使用認識、設定・学習内容・進行 | 設定だけ消える、次章で学習者の変更が消える |
| 章移動 | 保存失敗、同一オリジン再開、教材版不一致 | 保存前に遷移し編集が失われる |

日常の検証は、変更したパッケージの型確認・単体検証と境界のヘッドレス確認に絞る。全体検証は安定版ビルド時の規約に従う。画面付きElectronやOS入力は、この計画の検証には含めない。

## 切り戻し

通常URLの従来動作は維持し、学習モードの起動入口を止めれば通常編集へ戻れるようにする。故障した教材を、保護が外れた状態で自動再開しない。教材を閉じる、保存済み作品を別名保存する、通常Editorで開く、を本人が選べるようにする。

パッケージとEditorの対応版をまとめて直前の検証済み組合せへ戻す。作品、拡張設定、進行記録は削除しない。設定を理解しない旧版へ戻す場合も、データの保持を確認する。公開済み教材の同じ版を別内容で上書きしない。

## 効果とコストの判断

| 投資先 | 期待する効果 | コストの性質 |
| --- | --- | --- |
| プリセットとレジストリ | 章ごとの構成と問い合わせを説明しやすい | 初期の棚卸しが必要。その後の教材追加では再利用できる |
| Guide | GUI位置の説明を作品から共通化できる | GUI更新時の対象解決と実表示の追従が必要 |
| 入力欄の編集制限 | 第1章から本物の編集体験を提供できる | 小さな対象に限定すれば縦断検証しやすい |
| 任意の構造編集の制限 | 後半の自由度を上げられる | 操作経路とUndo等の組合せが多く、最も保守負担が大きい |
| 章間の自作内容の継続 | 自分の作品への愛着を育てる | 保存、版移行、再接続の設計が必要 |
| 全7章の演出と素材 | 次も遊びたい動機になる | 機構が固まる前に作ると手戻りが大きい |

最初の判断点は「第1章を理解して進められる」「自分の変更が動作に反映されたと分かる」「次章を試したい」である。利用者数や完走率の数値目標は、初回試遊の条件を決めてから設定する。工数は、T01の無効化監査とT06の変更前ガードの試作後に見積もる。
