# 初歩からソフトウェア工学までの学習経路

学習内容と学ぶ道具を段階的に解放する。課題に関係する部分だけを見せた作品を、制限されたEditorで編集し、自分の変更を実行して確かめる。学習済みの概念と道具を次の課題で使い、新しい概念に進む。

導入7章を全課程とはせず、導入7単元、プログラミング基礎6単元、データ構造とアルゴリズム8単元、ソフトウェア工学6単元、紙芝居のDSLとドメイン設計8単元の計35単元を初期案とする。一つの単元は複数の短いクエストに分けられる。導入以降の所要時間と難易度は試遊で調整し、すべてを同じ年齢で修了する前提にはしない。

## 三つの解放軸

| 軸 | 管理するもの | 例 |
| --- | --- | --- |
| 学習内容 | 前提となる概念、学習目標、到達の証拠 | 変数を使った得点管理から、リストと待ち行列へ進む |
| 教材の範囲 | 見えるスプライト・スクリプト・データと編集できる箇所 | 最初は一つの数値、次に短い処理、後にはモジュール間の接続を編集する |
| Editorの能力 | 起動時に使える機能セット | 検索、ミニマップ、タブ、分割、文書、差分、履歴を順に使う |

学習内容の進行とEditorの機能解放は一対一にしない。同じリストと分割表示を使って、スタック、キュー、探索を続けて学べる。新しい画面を出すためだけに課題を置かず、新しい概念を学ぶたびに画面を複雑にしない。

学習済みの概念は、図鑑や見本から参照できるようにする。未習得の教材内部や解答は既定で隠す。学習済みの道具は累積して使えるが、現在の課題を壊す操作は編集許可によって制限する。

## 到達経路

```text
導入 A01〜A07
  → 基礎 B01〜B06
      → データ構造 C01〜C04
          → 探索・整列 C05〜C08
      → 工学 D01〜D04
          → 共同開発 D05〜D06
  → 紙芝居制作 E01〜E04
      ＋ 基礎の手続き・データ、工学の仕様・テスト
          → ドメイン設計 E05〜E08
  → 目的別の自由研究
```

工学の仕様・テスト・整理は、基礎の後から並行して学べる。グラフ探索まで終えることを、最初のテストやリファクタリングの前提にしない。D06では、学んだデータ構造やアルゴリズムを作品の改良に使う。

## 導入編 A ゲームランドを開園する

[物語と章構成](course.ja.md)の7章を使う。

| 単元 | 主な概念 | 教材で開く範囲 | Editorの追加能力 |
| --- | --- | --- | --- |
| A01 ゲート | 順次実行、値と結果 | 数値入力一つ | なし |
| A02 音楽 | 条件と原因を探す | 指定された短い処理 | 検索 |
| A03 迷路 | 反復と回数 | 反復回数と関連する処理 | ミニマップ |
| A04 観覧車 | 役割分担とメッセージ | 二つの対象の合図 | 作業レイアウトとタブ |
| A05 おばけ屋敷 | 並行動作と順序 | 二つの処理のタイミング | 同一画面の分割 |
| A06 花火 | 命令の組合せ | 許可された短いスクリプトの構造 | パレットの調整 |
| A07 園長 | 目的を決めて改造する | 遊び場一つを選んで編集 | 作品情報と配置保存 |

A07は導入修了である。推奨導線は基礎編へ進む。経験者や自由制作をしたい学習者には、フルセットを選ぶ別の入口も残す。導入修了を全課程の修了や、すべての概念の習得とは扱わない。

## 基礎編 B ゲームランドを運営する

| 単元 | 物語と課題 | 学ぶ概念 | 編集範囲と道具 |
| --- | --- | --- | --- |
| B01 入園ゲートの係 | 入園者を数え、満員なら待ってもらう | 変数、状態、条件分岐 | 得点や人数の更新処理。検索と分割を再利用 |
| B02 パレードの演出 | 同じ動きを繰り返し、途中で条件を変える | 反復、終了条件、入れ子 | 限定した反復の中を編集 |
| B03 お店の注文 | 同じ注文手順を一つの処理にまとめる | 手続き、引数、重複の削減 | カスタムブロックの定義と呼出しを解放 |
| B04 ロボットの相談 | 二人が同時に仕事をしても結果を取り違えない | イベント、並行性、状態の分離 | 二つの対象と共有変数を表示 |
| B05 たくさんの風船 | クローンごとに違う色や動きを持たせる | インスタンスと個別の状態 | 元の処理とクローンの処理。素材ペインを必要に応じて解放 |
| B06 新しい遊び場 | 前の仕掛けを再利用して、別のルールを作る | 分解、再利用、説明 | 小さな対象全体を編集。追加のスクリプト転送を紹介 |

Scratchにもともとある変数、カスタムブロック、クローンをPlusの新機能として数えない。課題の許可範囲を広げて使わせる。ここでの新しいEditor能力は、目的が生じた時点の素材ペイン、追加プロパティ、転送等に限る。

## データ構造とアルゴリズム編 C ゲームランドの仕組みを作る

| 単元 | 物語と課題 | 概念と実装 | 目に見える判定 |
| --- | --- | --- | --- |
| C01 お店の商品帳 | 商品や得点を一覧で管理する | リスト、添字、レコード。最初は同じ形式の行から始める | 追加・参照・更新・削除後の一覧が意図した状態になる |
| C02 お皿の山 | 最後に置いたものから取り出す | スタック、push/pop、空の状態 | 操作列に対し取り出す順序が合う |
| C03 観覧車の行列 | 先に並んだ人から案内する | キュー、enqueue/dequeue、先頭と末尾 | 入場順が守られ、空のときも壊れない |
| C04 迷子の持ち物帳 | 番号から持ち主を見つける | キーと値、辞書。Scratchでは対応するリスト等で表現 | 存在する番号と存在しない番号を区別する |
| C05 宝物をさがす | 順番に調べて目当てを探す | 線形探索、見つからない場合、比較回数 | 正しい場所と比較回数を作品内に表示する |
| C06 半分ずつのヒント | 並んだ番号から効率よく探す | 二分探索、整列済みという前提、区間 | 同じデータで線形探索と結果を照合する |
| C07 パレードの順番 | 高さや得点の順に並べる | ソート、交換、正しさ。初版は一種類を丁寧に扱う | 並びが正しく、要素の欠落・重複がない |
| C08 迷路の道案内 | つながった道から出口を見つける | グラフ、訪問済み、幅優先探索とキュー | 出口のある迷路とない迷路で終了し、経路を示す |

各単元は、最初に視覚的な操作を試し、次にScratchのリストや手続きへ対応付ける。命令数や比較回数は、同じ入力に対して数えて比較する。端末速度だけでアルゴリズムの良し悪しを教えない。

新しい型付きデータ拡張がなければ成立しない教材にせず、最初は標準Scratchの表現で学べる範囲を使う。発展課題でJSONや構造化データを使うときに、その編集UIと対応能力を解放する。用語の暗記や計算量の記号は入口の条件にしない。

主に、リストの表示、二つの処理の比較、試行結果の文書化を使う。埋め込み文書エディターは、アルゴリズムの予想・結果を記録する目的で追加する。教材の制御台本を編集可能にすることとは分ける。

## ソフトウェア工学編 D みんなで育てるゲームランド

| 単元 | 物語と課題 | 学ぶこと | 道具と到達の証拠 |
| --- | --- | --- | --- |
| D01 注文を聞いて作る | 「満員でも壊れない」等の依頼を整理する | 要求、受け入れ条件、仕様 | 文書に条件を書き、確認できる形へ直す |
| D02 テスト係の部屋 | 普通の入力、空、上限等を試す | テスト、境界値、再現可能な入力 | 固定したテストデータと期待結果を使う。テスト実行基盤は追加実装 |
| D03 バグの足あと | 失敗を再現して原因を切り分ける | デバッグ、観測、最小の再現 | 検索・診断・観測値を使い、修正前に失敗を再現する |
| D04 工房のお片付け | 同じ動作を保ってコードを整理する | リファクタリング、責務、命名 | 変更前後のテストを比較し、振る舞いを維持する |
| D05 昨日と今日の作品 | 変更を分けて残し、仲間の変更を読む | バージョン管理、差分、レビュー | フォルダ、ローカルGit、文書。外部アカウントなしでも成立させる |
| D06 新装開園 | 役割を分けて改善し、配布する | 統合、互換性、リリース、振返り | 仕様・テスト・差分・版・配布物の対応を説明できる |

Editorの「作品診断」をプログラムの自動テストと同一視しない。D02のテスト基盤、D04の振る舞い比較等は、学習対象に合わせて固定入力と期待結果を実行する仕組みが別に必要である。

Gitの復元・ブランチ切替・作品全体の読込を、同じVM内で動く教材進行役に対して実行しない。初版のD05は保存・差分・履歴の読取りを中心にする。再読込を伴う工学課題では、教材の進行セッションを編集対象の作品から分離し、練習用作品を読み直しても案内が継続する追加設計が必要である。導入編の単一VMの実装だけで対応済みとはしない。

共同作業の入口は、二つの変更案を読み比べる形でよい。子どものGitHub登録、公開PR、AIエージェント、外部通信を必須にしない。利用可能なEditorのフルセットと、外部サービスを利用する許可は別に扱う。

## 学習進行のデータ

紙芝居の分岐は[DSLとドメイン設計](dsl-domain.ja.md)で詳述する。TurboWarp-kamishibai-docsの既存チュートリアルと詳細ガイドを利用し、用語、モデル、制約、境界を考える課題を加える。教員の割当・評価は[教員管理](teacher-management.ja.md)、各課題の絞り込みは[教材の提示方法](lesson-experience.ja.md)を参照する。

| データ | 内容 |
| --- | --- |
| 学習目標 | 概念IDと、何をできればよいかという観測可能な説明 |
| 前提 | 必要な概念・単元。章番号だけで一律に縛らない |
| 教材範囲 | 表示する対象、編集する対象、解答や制御処理の保護 |
| 必要な能力 | 現在の起動セットで必要なEditor機能 |
| 次の解放 | 達成後に案内する単元と、次回起動のプリセット |
| 到達記録 | 挑戦中、試行で達成、見本で通過、スキップを区別する |
| 作品の参照 | 学習者の作品ID、教材版、チェックポイント |

課題完了、概念の習得、Editor機能の使用可能状態を同じフラグへ押し込めない。指定された値を入れた一回の成功だけで、別の状況でも使えると判定しない。重要な概念は、短い別問題や自由制作で再び使う機会を置く。

教材設定は「次に進めたい単元」と「必要な能力」を申告する。実際の起動構成はホスト側の検証済みコース定義から生成する。作品が任意の機能を実行中に有効化する権限は持たない。

## 制作を広げる順序

まずA01〜A02で、マスクされた作品、制限されたEditor、実行中編集、次の解放を通して確認する。次にA07までを揃え、B01とC01、D01を一つずつ試作する。長期経路に必要な「データの見せ方」「仕様と結果の確認」が、導入の仕組みでどこまで成立するかを確かめる。

35単元を先に量産しない。教材制作者が新しい課題を設定と台本だけで追加できるか、コードの改修が必要な部分がどこかを確かめてから増やす。
