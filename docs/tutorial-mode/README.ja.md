# TurboWarp Plus Editor 段階解放と紙芝居教材の設計

2026年11月27日更新（初稿は11月19日）。対象はEditorの開発者と紙芝居教材の制作者。

素のTurboWarpに近い編集体験から始め、学習内容とEditorの追加機能を段階的に使えるようにする。学びに関係する範囲だけを見せた紙芝居作品を再生しながら、学習者は指定されたスプライト、スクリプト、入力欄を編集する。物語の進行を担う処理を保護し、編集した仕掛けだけを試して物語を続ける。導入の後は、初歩的なプログラミングからデータ構造とアルゴリズム、ソフトウェア工学へ進む。

本資料は実装仕様と教材制作手順の提案である。設定例、プリセット名、追加APIは、明記した既存APIを除き未実装。製品の利用手順としてそのまま適用できる状態ではない。

## 成立させる体験

1. 教材URLでEditorを開く。画面は、その章までに必要な機能だけを提供する。
2. 紙芝居を開始する。開始操作が必要な環境では、分かりやすい「はじめる」を表示する。
3. 登場人物が課題を出す。Guideが編集箇所や操作部位を指し示す。
4. 学習者は許可された部分を編集し、「ためす」を押す。作品全体の実行は止めない。
5. 変更した処理が実行され、作品内の結果を確認する。必要なら何度でも直して試せる。
6. 課題達成後、物語が続き、章の最後に保存と次章へのボタンが現れる。
7. 導入修了後は基礎編へ進める。学習を続けながら道具を増やし、最終的にフルセットのEditorを使う。任意に自由制作へ移る入口も持つ。

学習内容、教材内の表示・編集範囲、Editorの能力をそれぞれ管理する。新しい概念を学ぶたびに新しいEditor機能を追加する必要はない。機能を累積して使えることと、その課題で変更してよい範囲は分ける。

既存ユーザーが通常URLで開く場合の既定値は維持する。学習モードは専用URLから明示的に選ぶ。学習者には機能マスクの入力を要求しない。経験者は最初からフルセットへ進める。

## 三つの制御を分ける

| 制御 | 決まる時点 | 正本と役割 | 作品から変更できる範囲 |
| --- | --- | --- | --- |
| 機能セット | Editor起動時 | ホスト側レジストリ、プリセット、URL。どの追加機能を接続するかを決める | 必要な機能を申告できる。有効化済みセットを拡張することはできない |
| 学習モードの上限 | Editor起動時 | ホスト側ポリシー。別窓禁止、保存領域、使える制限機能を決める | 上限を解除できない |
| 課題の表示・編集許可 | 各課題開始時 | 作品のGuide拡張設定。見せるもの、変えてよいもの、判定条件を決める | 検証済みの名前付き課題を選べる |

実効的な操作許可は「ホストが提供する機能」かつ「学習モードで許可」かつ「現在の課題で許可」とする。機能が使えない場合、作品の設定で勝手に追加せず、起動構成が不足していることを説明する。

章内の「道具を手に入れた！」は、その章の起動時点で有効化済みの機能を物語上で紹介する演出とする。次章で必要な機能を増やすには、新しい起動構成で開く。実行中に起動フラグを書き換えない。

## 機能レジストリとプリセット

既存の186項目は調査・説明の細かさであり、そのまま186個の独立フラグにはしない。初版は20程度の機能群へまとめ、パッケージをまたぐ場合も利用者の目的で束ねる。

各機能に、変更しない文字列ID、英語名、日本語名、説明、所有パッケージ、必要な機能、対応ホスト、無効化の接続口を登録する。逆依存は依存リストから自動生成する。分析時のF001等とは別のID体系とする。

| 項目 | 方針 |
| --- | --- |
| 通常起動 | 従来の既定構成を維持する |
| `stock-v1` | 追加の編集機能を外し、通常のTurboWarpの編集画面と操作を基準にする |
| `quest-01-v1`〜`quest-07-v1` | 学習済みの機能を累積する。前の章で使えた機能を減らさない |
| `practice-v1`・`algorithms-v1`・`engineering-v1` | 後続コースの累積構成案。単元の必要性を確認してから配布する |
| `full-v1` | そのレジストリ版で定義されたすべての追加機能を選択する |
| 依存が足りない指定 | 診断する。明示マスクを黙って拡張しない |
| プリセットの作成 | 必要な依存を含めて生成・検証してから配布する |
| 未知のID・未知の有効ビット | 受け付けず、作品を開始する前に説明する |
| ホスト非対応 | 機能が選択済みでも使用可能とは扱わず、必須教材なら開始を止める |

「フルセット」は利用権限、ログイン状態、OS対応、拡張の実行承認を代わりに満たすものではない。同じプリセットを将来の版で黙って別の構成に変えない。

### ゼロから始めるときの境界

ゼロマスクの目標は、追加の編集UIと追加の編集動作を持たないTurboWarp相当の体験である。Plusのビルドと上流TurboWarpのバイト列が一致するという意味にはしない。文字入力の改良や右クリック項目、文書アイコン等も、追加動作として扱うなら無効化の監査対象になる。

教材には、紙芝居・Guide・設定の読込・編集許可の適用という基盤が必要である。この基盤を学習者向け機能マスクと分離する。ゼロマスクでも、学習モードでは案内と課題制限が動く。学習モードを指定しないゼロマスクでは、その基盤がUIや編集動作を追加しない。

無効化しても、作品内の未知データを捨てたり、実行に必要な拡張を自動削除したりしない。作品の再生に必要な能力と、その能力を編集するUIの提供は分けて判定する。

### 50桁の16進表現を使う場合

主な利用者向けの表現は名前付きプリセットとし、マスクはURL共有・比較・開発用の表現にする。50桁の16進数は200ビットであり、`0x`を含めると文字列長は52文字になる。

- レジストリ版をマスクと一緒に必須指定する。bit 0を最下位、文字列では右端とする。
- 現行例は20個のビットだけを割り当てる。ビット番号の再利用・意味変更はしない。
- 全ゼロは追加の編集機能なし。全Fは、その版の既知機能全部を選ぶ特別な別名とする。
- 全F以外では、未割当ビットを1にした指定を拒否する。通常の保存・出力では既知ビットだけを立てた正規形へ直す。
- 186項目を割り当てる版を将来作る場合、上位14ビットは予約となる。全Fの別名と通常の予約ビット検証を混同しない。
- マスクでユーザーの学習完了を証明しない。URLを直接開いてもよい設計とする。

起動引数の案は`twPlusFeatureSchema=proposal-v1`と、`twPlusPreset=quest-01-v1`または`twPlusFeatureMask=0x…`である。プリセットとマスクの同時指定は拒否する。プリセット指定時に、従来の個別URLフラグで機能を上書きさせない。競合する指定は診断する。マスクの処理では、200ビットを表せないJavaScriptの通常のビット演算を使わず、BigInt等で検証する。

`twPlusTutorial=1`と`twPlusCourse=game-land`は学習モードを選ぶ入力の案。作品データからこれらの起動値を上書きしない。URL引数名も含め、ここに示す統合仕様は未実装である。

## 編集範囲の制御

作品の実行データと、編集画面に表示するデータを分ける。隠したスプライトやスクリプトもVM内には残し、通常どおり動作させる。非表示を作品からの削除やScratchの「隠す」ブロックに置き換えない。

| 粒度 | 表示 | 編集許可の例 |
| --- | --- | --- |
| スプライト・背景 | 一覧、タブ、検索に見せるか | 選択、追加、削除、複製、名前変更 |
| スクリプト | 指定した処理だけ見せるか | 移動、複製、削除、組替え |
| ブロック | 関係するブロックだけ見せるか | 接続、切離し、移動、削除 |
| 入力欄 | 指定欄を案内対象にする | 数値・文字列・選択肢のみ変更 |
| 変数・リスト | 監視・一覧・検索に見せるか | 値、定義、要素の変更 |
| 素材 | コスチューム・音を見せるか | 追加、差替え、削除 |
| パレット | 使用できる種類に絞るか | 許可されたブロックのみ追加 |

初版は「対象スプライトと対象スクリプトを表示」「特定の入力欄だけ編集」を優先する。スクリプト構造の編集は後段とする。

編集権限はUIの見た目だけでなく、変更を反映する境界で検証する。ドラッグ、右クリック、キーボード、コピー・貼り付け、別タブ、文書フォーム、ファイル編集、バックパック等から同じ制限を守る。変更を反映してから監視して戻す方法は、実行中の作品が一瞬でも壊れるため主な防御にしない。

取り消し・やり直しは、許可された編集について使える。前の課題のUndoが現在の保護対象を変更する場合は、その操作を許可しない。初版は課題をまたぐUndo境界を設け、章単位の復旧データは別に残す。

この仕組みは学習時の誤操作を防ぐ。プロジェクトファイルを別のEditorで開けなくする、作者のコードを秘匿する、悪意ある同一ページの拡張を隔離する仕組みではない。

## 別画面と保存済み配置

学習モードでは、コード、ステージ、スプライト一覧、パレット、バックパック、ドロワー等の外部ウィンドウを生成しない。メニューを隠すだけでなく、ホスト生成と保存済み配置の復元にも同じ判定を適用する。同じdocument内のタブ・分割表示は課題に応じて使える。

通常用と教材用の画面状態を分ける。教材用はcourse ID・教材版・章を含む保存キーを持たせる。前に通常モードで作った別窓の配置が教材中に復元されないようにする。外部ウィンドウを含む古い配置は、主画面内の初期配置へ正規化する。

次章のURL、作品の保存、終了の入口は残す。`window.open`を一律に無効化するのではなく、Editorの外部表示機能を止める。

## 実行を続けたまま編集する

物語進行役と学習対象の処理を分ける。学習対象は、課題中に実行されていない短い処理とする。「ためす」でその処理を新しく呼び出す。VM全体の停止、緑の旗、`loadProject`、物語台本の再読込を課題の通常経路に使わない。

課題の状態は「準備 → 説明 → 編集待ち → 試行 → 結果判定 → 再挑戦または達成」とする。待つのは紙芝居の進行であり、他の演出やVM全体を止めない。試行中だけ学習対象を編集禁止にし、終わると再び許可する。

「そのまま再生を継続」は、実行中の任意のブロックの命令位置まで保ったまま自由に差し替える意味にはしない。コンパイラのキャッシュ破棄と、新しく起動した学習対象の処理への反映を実機能として検証する。Custom Actionのハット宣言や紙芝居の台本は、教材中の編集対象から外す。

既存のGit復元は作品の再読込につながるため、この経路へ流用しない。教材内の「もう一度」は試行用の座標や対象の状態だけを戻す。ソースの巻戻しが必要なら、その課題で許可された差分だけを戻す専用処理として後段で実装する。

## 現状と追加が必要なもの

| 対象 | 現状 | 今回必要な追加 |
| --- | --- | --- |
| 起動フラグ | `config/feature-flags.ts`とWeb用の読込が存在 | レジストリ、プリセット、全追加機能の無効化、依存診断 |
| 一部の追加機能 | 文書編集や転送等は独自の起動フラグを持たない | 既存の接続口で能力を渡し、機能パッケージ側で接続を省略 |
| Guide | 旧草案に表示・待機・対象照合とJudge通知のローカル試作記録がある。試作のSHA・検証ログは未確認 | 試作ソースと検証根拠の再特定、製品Editorへの統合、実Joyride表示の検証、編集許可の実装 |
| パレット | ブロックグループの表示設定がある | スクリプト・入力欄等の権限制御。パレット設定だけでは不足 |
| 作品フォルダ | ソース、素材、拡張JS、画面状態の読込・保存がある | Guide設定の保存契約、参照解決、SB3往復 |
| 紙芝居 | Custom Action Registryの拡張点がある | 人の操作待ちの時間制限、キャンセル、結果通知との接続 |
| 既存のブロック台本教材 | 再開始して編集を反映する教材がある | 再開始せず学習対象だけを試す新しい教材構成 |

| GUIのworkspace接続 | `components/gui/gui.jsx`がホストの`createWorkspaceAttachment`を呼ぶ。Editorのworkspace attachmentから`attachToWorkspace`へVM、document、Blockly取得口等を渡し、VM交換・破棄時にdisposeする | Guideの結線と固定Reactでの実表示。旧GUI内のattachmentファイルを前提にしない |

| ネイティブの値変更 | スライダー、リスト編集、CSV取込みが`variable-utils.js`の`setVariableValue`へ入り、同関数が値を直接更新する | 変更前の許可port、操作UI、各Plusパネルの同等の制限 |
| 拡張設定の保存 | VMの`serializeExtensionStorage`が使用拡張IDの集合でデータを絞る | Guide使用認識、設定と対象参照のSB3・フォルダ往復 |
