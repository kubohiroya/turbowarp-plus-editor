# 学習記録と教員コンソールの設計

Hour of CodeとCode.orgの課題型教材・教員向けダッシュボードを、課題割当、試行記録、完了の区別、支援のための参照例とする。Code.orgの全教材で同じ自動採点や提出作品の閲覧ができるという前提にはしない。

## 参考にする既存の仕組み

Code.orgの進捗画面には、クラス、学習者、授業・課題の単位で進捗を見る入口がある。課題の種類により自動検証と本人による完了の意味が異なるため、表示上の完了だけを理解の証明にはしない。[進捗の説明](https://support.code.org/hc/en-us/articles/115000693231-Viewing-student-progress)

課題の割当変更と過去の学習記録は別に管理され、割当は学習を始める入口にもなる。[割当と進捗](https://support.code.org/hc/en-us/articles/204874337-What-happens-when-I-assign-a-course-to-a-section-Can-I-assign-2-at-once)

作品を閲覧して確認する機能にも教材ごとの対応範囲があり、一部のHour of Code教材は対象外とされている。今回も自動判定、作品提出、教員の確認を分けて設計する。[課題のコードを見る](https://support.code.org/hc/en-us/articles/360047703872-How-do-I-view-a-student-s-code-on-an-individual-level)

## 管理する単位

| 単位 | 主な情報 |
| --- | --- |
| コース・教材版 | 単元、課題、前提、判定基準、起動プリセット |
| クラス・割当 | 教員、対象の学習者、教材版、開始する単元、公開範囲 |
| 学習者 | クラス内の識別子、作品、到達記録。実名は必須にしない |
| 課題 | 目的、編集許可、必要な道具、達成の方式 |
| 試行 | 試行ID、対象作品の版、初期条件、結果、使用したヒント等 |
| 提出 | 特定の作品スナップショットと本人の説明 |
| 評価 | 自動判定または教員確認、基準の版、フィードバック |
| 解放 | 次の教材、編集範囲、次回起動のEditor能力 |

## 完了の意味を分ける

課題ごとに、実行による自動判定、教員確認、体験の完了のいずれかを決める。作品のクリア通知は自動判定の入力であり、説明や設計の評価まで代用しない。

| 記録の軸 | 状態の例 |
| --- | --- |
| 進行 | 未着手、取り組み中、提出済み、完了、スキップ |
| 評価 | 未評価、自動判定で達成、再挑戦、教員確認済み、要修正 |
| 支援 | ヒント利用、見本利用、教員の支援 |
| 解放 | 通常の進行による許可、教員の個別許可 |

「見本で通過」「教員が次を許可」「自分の試行で達成」を区別する。教員が進行を解放しても、達成の証拠を捏造しない。一度の成功と概念の習得も区別し、別問題や自由制作で使う機会を設ける。

## 試行からクリアへ

1. 設定済みの課題を開始し、作品の版と初期条件を対応付ける。
2. 学習者が「ためす」を選び、保護されたJudgeが試行トークンを取得する。
3. Judgeが今回の作品内の状態を判定し、結果を通知する。
4. Guideが通知元、試行、課題の世代を確認し、一度だけ受理する。
5. 結果と証拠を保存し、物語の次の場面と次の解放を案内する。

教員確認が必要な課題は、提出した作品の版へ評価を結び付ける。提出後の編集を、提出時点の成果物と混ぜない。過去の達成記録は保持しつつ、現在の作品版が再確認を要することを表示する。

## 教員画面の最小構成

| 画面 | 教員ができること |
| --- | --- |
| クラスの進捗表 | 行を学習者、列を単元・課題として、状態を文字と記号で見る |
| 課題の詳細 | 直近の試行、結果、支援利用、提出作品、必要な道具を確認する |
| 学習者の詳細 | 到達した概念、未評価の課題、本人の作品へ移動する |
| 割当と支援 | 開始する単元、見せる課題、個別の進行許可、コメントを設定する |
| 教材管理 | 公開する教材版、判定基準、依存機能、対応Editorを確認する |

成功率や経過時間だけで順位付けせず、どこで支援が必要かを見つける。ログイン時刻、操作時刻、試行完了時刻を別に扱う。画面を開いていた時間を、考えた時間や理解度と断定しない。

## 実装を増やす順序

最初は個人利用のローカル記録と、明示的な書出し・読込みで課題と試行の形式を確かめる。この段階では全クラスのリアルタイム管理はできない。次に教員画面で持ち寄った記録・作品を確認する試作を行い、複数端末で共有する管理サービスへ進む。

学習記録モデルと教員UIは、既存の独立Guideパッケージを初期の実装先とする。共有サービスは、配置、認証、運用の方針を合意してから実装する。新しい管理用パッケージを、この資料だけで作成しない。

共有段階ではクラスの所属と教員の権限を確認し、本人と担当教員が必要な作品・記録だけを扱えるようにする。学習者のローカル通知は、そのまま改ざん不能な成績証明にはならない。厳密な評価が必要な場合は、提出作品の再実行や教員確認を使う。

URLの機能マスクは学習完了やクラス所属の証明にしない。本人が自由制作用のフルセットを開けることと、管理された授業の達成を記録することは別である。教員の解放変更も、Editor起動中の能力を勝手に切り替えず、課題の許可と次回起動の構成へ反映する。

## 記録と復旧

同じ試行IDの結果を二度数えない。停止、オフライン、再送、教材版の更新に対応し、記録の出所と判定基準の版を残す。教材を割り当て直しても過去の記録を削除しない。

初版はキーストローク、画面録画、カメラ映像を学習記録に含めない。必要な試行・結果・作品・支援情報に絞り、送信は利用者と運用方針に従う。教員画面は未実装であり、本資料の作成により子どものデータの収集や送信を始めるものではない。
