## 原因と変更

SVG複製よりも、矢印を輪郭へ接続するための `getPointAtLength` と、ミニマップの形状読み取り・DOM更新の交互実行が支配的だった。

- Code Viewsで輪郭の粗い探索を純JavaScriptで行い、候補区間の端と最終交点を従来と同じネイティブ計算で確定する。解釈できない形状、長さの差が0.05を超える形状、非有限の結果はネイティブ計算へ戻す。
- 同じ輪郭・高さの接続点を共有する。ズームの変換誤差によるキャッシュミスを、従来の精密化の許容誤差0.001より小さい0.000001単位で吸収する。返す高さは実際の要求値を保つ。
- ミニマップは全形状の読み取りを先に行い、その後で既存パスを更新する。
- `svg-path-properties` は既存GUIのWebpack 4と接続できる1.3.0に固定し、配布物のLICENSE本文をCode ViewsのNOTICEへ同梱する。

プロファイルは計測器を付けた各1回で、上表の各5回の時間とは別に扱う。

| 処理 | 比較前 呼出回数 / ms | 候補 呼出回数 / ms |
|---|---:|---:|
| cloneNode | 59 / 10.5 | 59 / 10.4 |
| getPointAtLength | 9427 / 906.8 | 2458 / 243.6 |
| getScreenCTM | 4146 / 301.1 | 4146 / 10.5 |
| Layout | 2391 / 327.7 | 71 / 61.7 |
| UpdateLayoutTree | 2401 / 383.9 | 85 / 352.3 |

DOM APIとtimelineの時間は重なるため、合計しない。

- 実作品の1046種類の輪郭で左右・複数の高さの8368通りを比較し、新旧の端点の最大差は0だった。
- 実Editorで平行移動・ズームの追加 `getPointAtLength` はいずれも0回。59スクリプト、ミニマップ2320パス、表示中の関係144件を確認し、全ターゲットのブロック・コメントのJSONは一致した。
- 所有先の関連ブラウザーテスト46件、配置・関係の単体テスト19件が成功。ドラッグ、輪郭の変更、折りたたみ、Z/N、テーマ、ズーム、矢印の接続と編集画面を含む。
- 実Editorの対象8ケースでZ/N切り替え、メッセージの線種、編集、自由配置の座標、接続、再配置のUndo/Redo、ズーム、分割パネル、ミニマップを確認。依存固定とNOTICEの対象8テストも成功。

## 最新mainへの統合

性能比較の前提を保った後、Editorの最新main `6a08e38815c07af14331217dd06fd3137f12c762` を取り込み、Code Views 0.26.7の候補を統合した。Workbenchはmainの正式版0.40.2を使い、既存のoverridesによる単一版の固定を維持する。統合結果は隣接JSONの `latestIntegration` を参照する。正式なnpm公開後にregistryの内容・integrityを確認してEditorの固定を確定する。Scratch GUIのソース差分はない。
